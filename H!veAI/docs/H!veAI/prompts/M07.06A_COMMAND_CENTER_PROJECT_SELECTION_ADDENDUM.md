## User manual-QA requirement

The user explicitly requires the Command Center / Global Overview Projects rail to behave like a project selector for the central Current Project panel.

The current implementation navigates away on row click:

```tsx
onClick={() => navigate(`/projects/${project.id}`)}
```

That is not the requested Global Overview interaction.

## Required behavior

On the Command Center route only:

1. clicking a row in the left `Projects` rail must remain on the Command Center / Global Overview route;
2. the clicked project becomes `selectedProjectId` in the shared session-level registry/project state;
3. the selected row gets a clear but restrained active style;
4. the central `CURRENT PROJECT` header immediately changes to the selected registered project's exact identity;
5. all registry-backed central fields must derive from the same selected record;
6. task/workflow/metrics fields that do not yet have M08/M09 evidence must render neutral truthful placeholders and must not retain another project's data;
7. selecting `Bulk-Edit` must update the central workspace to `Bulk-Edit` without page navigation, reload, or restart;
8. selecting `AI-Commerce-HQ` must update it back to `AI-Commerce-HQ` the same way;
9. selected project remains selected when the user returns to Command Center during the same app session;
10. if selected project is removed/archived or no longer eligible, choose a deterministic live Registry fallback and synchronize `selectedProjectId`;
11. no stale async request may overwrite a newer selection.

Do not use fixture identity in Tauri mode.

## Separate full-cockpit navigation

The central selected-project workspace must expose a distinct `Open cockpit` action.

That action, and only that explicit cockpit action from the Global Overview project-selection interaction, should navigate to:

```text
/projects/<selectedProjectId>
```

The route must open the exact selected project with the existing no-cross-project-flicker contract.

Sidebar Project Shortcuts and the full Projects page may keep their route-oriented behavior unless the active M07.06 contract says otherwise. The specific new requirement here is that the **Global Overview Projects rail selects in place**.

## Accessibility

- selected row exposes an accessible selected/current state, e.g. `aria-pressed`, `aria-selected`, or equivalent semantically correct implementation;
- keyboard activation changes selected project without navigating away;
- active styling is not conveyed by color alone.
