# M08.00A — FMCG Neon Liquid Glass UI Addendum

## Purpose

This addendum extends the active `M08.00_APP_PRESENTATION_BOOTSTRAP_PROMPT.md` only.

It does **not** start M08 Task Source Discovery.

The user wants the proven button/table visual language from the FMCG ERP project adapted into H!veAI while preserving the already-approved M07 layout and behavior.

Reference design source:

`Sekiph82/fmcg-erp-system`

Canonical reference file:

`frontend/src/app/globals.css`

The reference design system is explicitly named:

`NEON LIQUID GLASS DESIGN SYSTEM`

Relevant reference primitives include:

- `.glow-button`
- `.glow-button-secondary`
- `.glass-table`
- `.liquid-glass`
- `.glass-panel`
- `.neon-border`
- `.neon-focus`
- shared cyan / blue / indigo / purple / pink glow tokens

Do not copy the entire FMCG visual system blindly. Adapt these primitives to H!veAI's current navy/black + cyan/blue/violet/magenta identity and the new hive background.

---

# Scope

Apply the neon-liquid-glass treatment primarily to:

1. primary buttons;
2. secondary buttons;
3. compact icon/action buttons where appropriate;
4. real table containers, table headers, rows, and hover states;
5. focus-visible states for interactive controls.

Optional, restrained use is allowed for panel/card borders only when needed to keep the new background legible through glass surfaces.

Do **not** redesign page hierarchy or turn every surface into a glowing card.

---

# Visual target

The application background image introduced by M08.00 should remain visually present behind the UI.

Interactive surfaces should feel like semi-transparent dark glass floating above the hive background:

- dark translucent navy glass;
- subtle backdrop blur and saturation;
- thin cyan/blue border;
- restrained violet secondary glow;
- faint white inset highlight;
- slightly stronger glow on hover/focus;
- no cartoon neon;
- no excessive bloom;
- no readability loss.

The result should feel like a premium AI engineering command center, not a gaming HUD.

# Buttons

Adapt the FMCG `.glow-button` / `.glow-button-secondary` behavior into H!veAI's existing primary and secondary button classes.

Primary target character:

```css
background: linear-gradient(
  135deg,
  rgba(37,99,235,.85) 0%,
  rgba(79,70,229,.80) 50%,
  rgba(109,40,217,.75) 100%
);
backdrop-filter: blur(10px);
border: 1px solid rgba(96,165,250,.55);
box-shadow:
  0 0 0 1px rgba(96,165,250,.35),
  0 0 14px rgba(59,130,246,.35),
  0 0 28px rgba(139,92,246,.20),
  inset 0 1px 0 rgba(255,255,255,.10);
```

Hover may brighten and increase glow slightly, with at most a subtle `translateY(-1px)`.

Secondary buttons should use translucent dark glass rather than a strong gradient and a gentler cyan/blue glow.

Requirements:

- preserve existing dimensions and layout contracts unless a tiny padding correction is required;
- preserve accessible labels;
- preserve disabled semantics;
- preserve keyboard focus visibility;
- no persistent animation loop;
- no large movement or bounce.

# Tables

Adapt the FMCG `.glass-table` treatment for all true table surfaces introduced or currently present in H!veAI.

Target character:

```css
background: rgba(15,23,42,.58);
backdrop-filter: blur(14px) saturate(150%);
border: 1px solid rgba(96,165,250,.22);
box-shadow:
  0 0 0 1px rgba(59,130,246,.14),
  0 0 22px rgba(59,130,246,.10),
  0 12px 40px rgba(2,8,23,.45),
  inset 0 1px 0 rgba(255,255,255,.05);
```

Header:

- translucent dark navy;
- thin cyan/blue separator;
- restrained blue/cyan header text;
- preserve H!veAI typography sizing.

Rows:

- thin low-opacity separators;
- hover uses a very light blue transparent fill;
- no row movement;
- selected/active row keeps existing semantic state and gains only a restrained glow/border accent.

Do not fabricate tables on routes that currently do not use tables.

---

# Glass panel compatibility with the new background

Because M08.00 introduces a global hive background image, existing opaque surfaces may hide it completely.

Where needed, reduce only the relevant panel surface opacity enough to allow a subtle amount of the background to read through.

Use backdrop blur to preserve text legibility.

Do not make every panel transparent.

Critical Command Center content must remain readable at a glance.

---

# Performance and Tauri/WebView constraints

Backdrop filters and multi-layer shadows can be expensive.

Requirements:

- keep blur/shadow layers bounded;
- avoid applying heavy blur independently to dozens of nested children;
- prefer shared container glass surfaces;
- no animated blur;
- no continuous box-shadow pulsing;
- no canvas/WebGL effects for glassification;
- preserve smooth desktop interaction in WebView2.

If the system reports reduced motion, do not add transform-heavy hover motion beyond basic state changes.
