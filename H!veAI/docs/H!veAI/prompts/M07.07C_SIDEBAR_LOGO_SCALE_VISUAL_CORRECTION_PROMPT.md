## Current defect

Current production CSS contains the following effective sizing in `H!veAI/src/command-center.css`:

```css
.brand{padding-bottom:18px}
.brand-logo{
  background:transparent;
  border:0;
  border-radius:0;
  height:34px;
  max-width:154px;
  object-fit:contain;
  object-position:left center;
  padding:0;
  width:100%
}
```

The sidebar is approximately 220 px wide, while the fixed `height:34px` and `max-width:154px` cause the wide combined logo to render far too small. The screenshot reviewed by the user shows a tiny brand mark in the top-left with a large amount of unused horizontal space.

### Preferred implementation direction

Make the sizing **width-driven rather than fixed-height-driven**.

A suitable implementation should be conceptually equivalent to:

```css
.brand {
  padding-left: 0;
  padding-right: 0;
  /* preserve appropriate bottom spacing */
}

.brand-logo {
  display: block;
  width: 100%;
  max-width: none;
  height: auto;
  object-fit: contain;
  object-position: left center;
}
```

You may choose a very small horizontal inset if required for visual breathing room, but the final rendered logo should use almost all of the available inner sidebar width.

Do not blindly copy these declarations if existing responsive rules require a safer equivalent. Inspect all competing `.brand`, `.brand-logo`, `.sidebar`, and mobile rules first.
